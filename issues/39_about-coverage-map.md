## 背景

ポートフォリオの方針は「技術リストではなく判断力を示す」。一方で、Works は具体（個々のプロダクト）を担い、About は抽象（この人は何をどこまでカバーする人か）を担う分担にしたい。現状の About は物語（本文）と時間軸（年表）はあるが、「空間軸の広がり＝カバー領域」を示すブロックがない。

トップ（Works）は Issue 36-38 でファーストビューを軽くしてきた経緯があり、そこへ足すのは重い。About の年表の上に置く。

## 構成仕様

上から順に3つの部品を縦に並べる。About.astro 内の他ブロックと同様、データはコンポーネント内に直書きする（works.ts からの導出はしない。抽象表現なので代表技術は手選びでよい）。

### 1. セクション内ラベル

既存の `ABOUT` ラベルと同型の font-mono 小ラベル。文言は `COVERAGE`。

### 2. Business 層（1枚のカード）

- 左に見出し「Business」、右に説明「課題の発見と技術への翻訳 — 経営12年 / 外部CTO」。
- 直下に下向きの接続記号（↓）を中央配置し、5領域の枠へ視覚的に接続する。
- **5領域の表の1行にはしない**。行に混ぜると「6領域の並列」に読めてしまい、
  「課題を翻訳して5領域に落とす」という縦の関係（About 見出し「曖昧な課題を技術に翻訳し」の図解）が消えるため。

### 3. 5領域の枠

- 外枠（ボーダー1本の囲い）の内側上部に、中央揃えで「1人で設計・実装・運用」と置く。
  この外枠とラベルが本ブロックの核。これが無いとただのスキル表になる。
- 枠内は5行の表（左列: 領域名、右列: 代表技術。右列は muted トーン）:

  | 領域 | 代表技術 |
  |---|---|
  | Frontend | React / Vue / TypeScript |
  | Backend | C# (.NET) / Python / Go |
  | Data / AI | LangGraph / RAG / Text-to-SQL |
  | Infra / SRE | NixOS / Cloudflare / AWS / CI/CD |
  | IoT | ハードウェア〜クラウド連携 |

  行間は薄い罫線（年表と同系のボーダー色）で区切る。ヘッダー行（「領域」「該当」等）は置かない。
- 枠内右下に小さく「具体例 → Works」のリンクを1本置き、トップ（`/`）へ飛ばす。
  各行から個別 Work へのリンクは張らない（具体は Works の担当。橋はこの1本だけ）。

### 挿入位置

About.astro の本文2段落を包む `div`（現状 26-40 行目付近）と、年表ブロック（`mt-12 space-y-6` の div、42 行目付近）の間。

### 制約

- 既存トーンを維持する: font-mono の小ラベル、poi 系カラートークン、ライト/ダーク両対応。
- 5領域は行方向（縦積み）なのでモバイル専用の分岐は原則不要。右列の技術名が折り返しても崩れない組みにする。
- 代表技術は各行3〜4個まで。網羅しない（網羅はリストに退行する）。
- 他ファイル（works.ts・index.astro・他セクション）は変更しない。

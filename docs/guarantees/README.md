# Guarantee Ledger

このリポが外へ約束している振る舞いと、それを守るテストの一覧である。約束が破れればテストが落ちるので、
ここに書いたことは気づかないうちに実装とずれていかない。**ここに載っていない振る舞いは約束ではなく、予告なく変わりうる**。
対象は `src/lib/api.ts` が公開する Hono ルート（`/api/*`）の入出力（ステータスコード・レスポンスの形）と、`src/lib/contact-form.ts` の `buildContactBody` が送信用に組む値である。
ハンドラ内部の実装（Telegram と Turnstile へ実際に送る内容）と、Astro のページ・コンポーネントの描画結果は対象外とする。

- 目的: いま何を約束しているかを1か所で読む。変更の前に、守る約束をここから引く。テストの無い約束を Gaps に残す
- 分け方: 約束の対象（API のルート・公開関数）ごとに1ファイル。テストファイルや Issue の単位では分けない。新しい対象を作ったときだけファイルを足す
- 書き方: 各ファイルに「保証｜対応テスト」の表を1つ置き、1行に約束を1つ、宣言文で書く。出典・経緯・設計の理由は書かない（Issue が持つ）。ページの見た目、手で確かめる画面の振る舞い、型検査、サイトのデータや文字の大きさを点検する開発用のテストは載せない。約束が10行以上のファイルは、何についての約束かで `##` の見出しを立て、見出しごとに3行以上の表を置く。見出しは行の主語になる名詞句にする。10行未満のファイルには見出しを置かない（ファイルは分けない）
- 引き方: 変更の前に、その対象のファイルを開いて守る約束を読む。テストが落ちたら、テストの名前で台帳を検索すると、破れた約束の行が見つかる。約束が守られていることは、全テストを流す CI が確かめる。コードのファイルから約束を引く仕組みは置かない（実装とテストの名前は1対1でなく、機械では正確に引けない）
- 運用: 変更の前にこの README を読み、変更が触れるファイルから「維持する保証」を引く。約束を足す・変える・消すときは、承認を受けた保証節の文のまま、該当するファイルの表に行を足す・直す・消し、対応テストも同じ変更で直す。行を足して10行以上になったら、同じ変更で見出しを立てる。Issue や作業ごとにファイルや節を起こさない。テストの無い約束は Gaps に書き、テストを足したら移す。乖離は `guarantee-audit` で棚卸しする
